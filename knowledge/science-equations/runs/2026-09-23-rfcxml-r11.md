# RFCXML source-lane reconciliation

## State reconstructed from main

Current `main` already owns the source-first data plane: occurrence validation lives in `scripts/science-equations/materialize-parquet.py`, Parquet is canonical bulk storage, Internet Archive is the publication surface, and recent PMC/JATS and LMFDB lanes use that shared contract. The historical RFCXML PR predated that consolidation and duplicated storage/schema work that no longer belongs in the lane.

This run therefore keeps only the still-exclusive RFC Editor source work and rebases its record shape on the contemporary `OccurrenceV1` contract.

## Source/corpus worked

- source: RFC Editor RFC series / RFCXML;
- source id: `ietf-rfcxml-formal-blocks`;
- acquisition: official RFC Editor rsync mirror `rsync.rfc-editor.org::rfcs`;
- initial extraction lane: non-empty RFCXML `sourcecode` blocks whose `type` is `abnf` or `pseudocode`;
- provenance class: `attested`;
- adapter: `scripts/science-equations/harvest-ietf-rfcxml.py`;
- descriptor: `data/science-equations/sources/ietf-rfcxml.json`.

The adapter emits exact sourcecode bodies as `expression_original`, records the RFC and block locator, hashes both the attested record payload and exact expression, and preserves IETF Trust policy metadata. This fixes the historical lane's pre-consolidation field names (`original_expression`, `original_encoding`, `original_text_sha256`) by emitting the current canonical names directly.

## Snapshot policy

The rsync mirror is mutable. A valid bulk acquisition must therefore create a deterministic inventory of selected `rfc*.xml` files containing relative path, byte size and SHA-256, then use the inventory digest as `source_snapshot`. No date-only snapshot identifier is accepted.

## Validation boundary

This reconciliation intentionally does not claim a production acquisition. Real corpus rows, Parquet rows and Internet Archive items remain **0** until an executor with network access acquires the official mirror, computes the inventory digest, runs the adapter, validates the JSONL through `materialize-parquet.py --validate-only`, materializes Parquet and verifies publication.

The repository CI is expected to validate repository policy, formatting/build invariants and the change-card surface. Bulk acquisition/materialization/publication remains outside GitHub Actions.

## Coverage gained

The Atlas gains a source-native computer-science/protocol lane for formal grammars and pseudocode from RFCs without reintroducing a parallel schema or publisher. The work is now additive to, rather than competitive with, the PMC/JATS, OEIS, Wikidata and LMFDB lanes already present on `main`.

## Next executable step

On an authorized executor with outbound network and `rsync`:

1. mirror the RFC Editor `rfcs` module;
2. persist the deterministic inventory digest;
3. run `harvest-ietf-rfcxml.py` with that digest as `--snapshot`;
4. run `materialize-parquet.py --validate-only` on the emitted JSONL;
5. materialize Parquet and publish through the canonical Internet Archive publisher;
6. persist only the lightweight verified manifest and observed counts in Git.
