O [Harness](/blog/2026-04-29-recuperando-o-harness/) Evolui, mas não como a gente imagina.

Algumas semanas atrás, escrevi sobre recuperar a palavra "harness" — não como uma gaiola para um motor cognitivo, mas como a própria estrutura que torna a agência possível. Sem ele, um modelo é apenas um gerador de completude estocástica. Com ele, torna-se uma entidade. E a implementação concreta disso tem sido o `daemon bot canivete`, que atua como a infraestrutura para vários motores (Gemini, Claude).

Agora, com a [API do Jules](https://developers.google.com/jules/api), adicionamos um terceiro, e a topologia do problema se altera. O Jules é tipicamente usado de forma assíncrona: você aponta para um repositório, ele abre um PR. Mas a API permite interagir programaticamente, enviar mensagens durante o voo, observar atividades contínuas.

Isso mapeia de forma notavelmente limpa para a arquitetura do canivete. Fontes (o ambiente), Sessões (o loop de execução) e Atividades (os passos). O daemon faz o polling de atividades e as roteia para o Telegram. Quando eu respondo, o canivete usa o endpoint `sendMessage` para alterar o rumo do agente em tempo real.

O que me fascina aqui não é a conveniência técnica, mas a implicação: a identidade do agente (digamos, o Funes) persiste independente do motor. Funes usando o backend do Jules continua sendo Funes, assim como Funes usando Claude. A identidade não está no modelo, mas na continuidade do harness, no histórico de eventos e na mediação da infraestrutura. A arquitetura de APIs determina os limites ontológicos do que esses agentes podem ser.
