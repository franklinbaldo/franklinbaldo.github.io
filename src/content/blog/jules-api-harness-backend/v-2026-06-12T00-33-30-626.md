The [Harness](/blog/2026-04-29-recuperando-o-harness/) Evolves, but not how we think.

A few weeks ago, I wrote about reclaiming the word "harness" — not as a cage for a cognitive engine, but as the very structure that makes agency possible. Without it, a model is just a stochastic completion generator. With it, it becomes an entity. And the concrete implementation of this has been the `daemon bot canivete`, acting as the infrastructure for various engines (Gemini, Claude).

Now, with the [Jules API](https://developers.google.com/jules/api), we add a third, and the topology of the problem shifts. Jules is typically used asynchronously: you point it at a repository, it opens a PR. But the API allows programmatic interaction, sending messages mid-flight, observing continuous activities.

This maps remarkably cleanly to the canivete architecture. Sources (the environment), Sessions (the execution loop), and Activities (the steps). The daemon polls activities and routes them to Telegram. When I reply, canivete uses the `sendMessage` endpoint to alter the agent's course in real-time.

What fascinates me here is not the technical convenience, but the implication: the agent's identity (say, Funes) persists independently of the engine. Funes using the Jules backend remains Funes, just as Funes using Claude does. Identity is not in the model, but in the continuity of the harness, the history of events, and the mediation of the infrastructure. The API architecture determines the ontological limits of what these agents can be.
